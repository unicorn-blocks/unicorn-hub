# Stripe 支付集成测试文档

## 概述

本文档描述了如何测试 Stripe 支付集成的各种场景。所有测试都使用 Stripe 提供的测试卡号，**不需要真实银行卡**。

## 环境准备

### 前置条件
- 开发服务器正在运行：`npm run dev`
- 访问地址：`http://localhost:3000`
- 已配置 Stripe 测试密钥（`.env` 文件）

### 测试卡号来源
所有测试卡号来自 [Stripe 官方文档](https://stripe.com/docs/testing)

---

## 测试场景

### 场景 1：✅ 支付成功

**目标**：验证成功支付流程

**步骤**：
1. 访问 `http://localhost:3000/checkout`
2. 填写表单信息
   - 邮箱：任意有效邮箱（如 `test@example.com`）
   - 名字/姓氏：任意
   - 地址：任意
   - 城市：任意
   - 国家：任意
3. 选择"信用卡"支付方式
4. 点击"完成订单"按钮
5. 在 Stripe Checkout 页面填写卡片信息
   - **卡号**：`4242 4242 4242 4242`
   - **有效期**：`12/25`（或任意未来日期）
   - **CVC**：`123`（或任意 3 位数字）
6. 点击"Pay"按钮

**预期结果**：
- ✅ 支付成功
- ✅ 重定向到 `/payment/success` 页面
- ✅ 显示"Payment Successful! Thank you for your purchase"
- ✅ 显示折扣凭证信息
- ✅ 显示"What happens next?"步骤

**验证清单**：
- [ ] 页面标题正确
- [ ] 成功消息显示
- [ ] 折扣凭证信息显示
- [ ] 后续步骤显示
- [ ] "Back to Home"按钮可点击

### 场景 6：❌ 不正确的 CVC

**目标**：验证 CVC 验证

**说明**：Stripe 测试环境中，`4000 0000 0000 0127` 这张卡的 CVC 验证行为可能不如预期。建议跳过这个场景，或者使用 `4242 4242 4242 4242` 配合任意 CVC 来验证支付流程。

**替代方案**：
- 使用 `4242 4242 4242 4242` + 任意 CVC → 支付成功
- 使用 `4000 0000 0000 0002` + 任意 CVC → 卡被拒绝

**验证清单**：
- [ ] 支付流程能正确处理各种卡片状态

## 浏览器开发者工具调试

### 查看网络请求
1. 打开浏览器开发者工具（F12）
2. 切换到"Network"标签
3. 执行支付操作
4. 查看请求和响应

**关键请求**：
- `POST /api/payment/stripe/checkout-session` - 创建 Checkout Session
- 重定向到 Stripe Checkout 页面

### 查看控制台日志
1. 打开浏览器开发者工具（F12）
2. 切换到"Console"标签
3. 查看是否有错误或警告

**预期日志**：
- 支付成功：无错误
- 支付失败：可能有错误信息

### 查看本地存储
1. 打开浏览器开发者工具（F12）
2. 切换到"Application"标签
3. 查看 Local Storage 和 Cookies

## 常见问题

### Q1：如何重置测试状态？
**A**：清除浏览器 Cookie 和本地存储
1. 打开开发者工具（F12）
2. 右键点击"Application"
3. 选择"Clear site data"

### Q2：支付后没有重定向怎么办？
**A**：检查以下几点
1. 检查浏览器控制台是否有错误
2. 检查网络请求是否成功
3. 检查 `.env` 文件中的 `NEXT_PUBLIC_APP_URL` 是否正确

### Q3：Stripe Checkout 页面加载很慢？
**A**：这是正常的，Stripe 需要时间加载。如果超过 10 秒，可能是网络问题。

### Q4：如何测试 webhook？
**A**：需要配置 Stripe CLI
```bash
stripe listen --forward-to localhost:3000/api/webhooks/stripe
```
